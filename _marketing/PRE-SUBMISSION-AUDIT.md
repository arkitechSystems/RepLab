# Pre-Submission Audit — REPLAB

## Summary

Codebase is in good shape for submission. The pre-launch feature flags (FF_FEATURED, FF_CHALLENGES, FF_TRAINERS) all gate their respective surfaces correctly, the Apple-reviewer demo account ships clean of unimplemented features, and PII handling (Sentry `sendDefaultPii: false`, dev-only client console output, no token/password logging) is sound. The remaining issues are cosmetic-but-shippable: a handful of mixed-case "RepLab" strings in user-facing copy that violate the brand spelling rule (should be REPLAB), one stale "replab.app" domain in a generated PDF, one dev-only `.env.example` pointing at the dead `will-fit.shop` domain, and a few "coming soon" teasers that hint at unbuilt features. Nothing here would block submission, but the mixed-case brand strings should be cleaned up before press materials start screenshotting the app.

## Blocking (must fix before submission)

None. The hard rebrand work (URL switch, bundle ID, email templates, gating) is already complete and shipping correctly.

## Verified clean

- **No "WillFit" / "willfit" / "will-fit" strings in user-facing client code.** The remaining `@willfit.demo` email pattern in `server/db.js` and `server/routes/auth.js:236` is the demo-account email-domain filter — it's a server-side LIKE pattern used to exclude demo accounts from analytics, not user-facing. Code comments referencing the old name (e.g. `Workouts.jsx:4920` "the old 'Welcome to WillFit' empty-state card") are inline comments only.
- **No dead `https://will-fit.shop` URLs in shipping client/server code.** All client URLs use `https://replab-fitness.com` (Workouts.jsx:1496, 1523) or `https://replab-videos.onrender.com` for the CDN. `server/config.js:12` defaults `APP_URL` to `replab-fitness.com` correctly. Stale references are confined to `MIGRATION.md`, `_marketing/`, `.env.example`, and admin migration-checklist data which is auth-gated.
- **No TODO / FIXME / HACK / XXX in shipping JSX strings.** Two markers exist in `client/src/pages/Profile.jsx:143-144` and they're code comments explaining a phone-number normalizer, not user-facing copy. Server-side `TODO|XXX` hits are inside `server/package-lock.json` integrity hashes (string coincidences).
- **No password / JWT / token leaks via `console.log`.** Client-side `console.error`/`console.warn` are uniformly wrapped in `if (import.meta.env.DEV)` guards (Profile.jsx, Workouts.jsx, Calendar.jsx, WorkoutSession.jsx, push.js, deepLink.js, AuthContext.jsx, etc.). Server-side `console.log` is limited to (a) boot banners, (b) scheduler tick logs that only print user IDs + counts, and (c) seed-script status messages. No raw request bodies, password hashes, or JWTs are logged anywhere in `server/routes/*` or `server/middleware/*`. `Sentry.init` in `client/src/sentry.js:15` sets `sendDefaultPii: false`.
- **Hardcoded `test@example.com` / `jane@example.com` etc.** Limited to `server/tests/` and `server/scripts/test-transactional-emails.js` — test fixtures only, never executed by the production server. `apple-reviewer@replab-fitness.com` is the intentional reviewer-demo email (documented in `_marketing/app-review-notes.md`) seeded only via the manual `seed-apple-reviewer.js` CLI.
- **"Coming Soon" gating coverage.** Verified gating:
  - `FeaturedWorkoutSession.jsx` (lines 1339, 1477, 1653) is reached only via `/featured-session*` routes, which `FeaturedGate` (App.jsx:124) redirects unflagged users away from.
  - Challenges deep section (`Workouts.jsx:3479` Plank Hold "Coming Soon" card) sits inside `if (selectedGroup === 'challenges')` at Workouts.jsx:3357 with a same-function guard at 3353 redirecting unflagged users.
  - Featured Trainers section (`Workouts.jsx:3839`) is guarded at 3243 by `if (selectedGroup === 'partners' && !trainersUnlocked) { ... setSelectedGroup(null); return null; }`. The `trainersUnlocked` flag from FF_TRAINERS is wired in at `Workouts.jsx:1025`.
  - The Featured Workouts library card (`Workouts.jsx:5180-5240`) and Challenges library card (5763-5829) both check their respective `*Unlocked` flag for `onClick` / `cursor` / `opacity` — locked state renders the "Coming Soon" copy non-interactively.
  - The Featured Workouts library card video CDN reference (`Workouts.jsx:4674`, line 5219) is inside the always-visible promo area but is decorative; it does not navigate.
- **Test routes (`/test/*`).** Email-allowlisted via `TestRoute` (App.jsx:108-114) so `RepLabFeedTest`, `LoginScreensTest`, `NikeCardsTest`, `RequestTrainerTest`, `LandingPageAuroraTest`, etc., never render for the Apple reviewer account.
- **App Store badges.** Both badges in `client/src/components/AppStoreBadges.jsx` default to `disabled = true` — they render as non-interactive "Coming soon to the App Store/Google Play" elements until launch, no dead store URLs.
- **CSP / origin / outbound URL allowlist.** `server/index.js:103-112` restricts `connect-src` / `frame-src` / `form-action` to known third parties (Stripe, YouTube nocookie, PostHog, Sentry, ip-api, Resend, Anthropic). No old-domain entries.
