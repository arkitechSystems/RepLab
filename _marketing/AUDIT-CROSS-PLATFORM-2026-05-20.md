# REPLAB — Cross-Platform Consistency Audit (2026-05-20)

## Verdict

**RED.** Capacitor shell ships but multiple native systems are wired in JS only — no native registration, no Firebase config, splash never hides, no keyboard plugin, no haptics on iOS, no deep-link bootstrap, no Sentry platform tag, dashboard has zero responsive classes despite `TARGETED_DEVICE_FAMILY = "1,2"`.

## Platform-specific configuration state

- **iOS** — Bundle `com.replab.fitness`; deployment target 15.0; SPM-based (no Podfile); plugins registered in `client/ios/App/CapApp-SPM/Package.swift:14-22`: App, Device, Haptics, Preferences, PushNotifications, SplashScreen, StatusBar. **`@capacitor-firebase/messaging` is in `client/package.json:12` but NOT in Package.swift.** No `App.entitlements` file (`Bash find` returned 0 results) — Associated Domains + APS Environment capabilities are not declared. No `GoogleService-Info.plist`. AppDelegate is stock template (`client/ios/App/App/AppDelegate.swift:1-49`). Versions: `MARKETING_VERSION 1.3.03`, `CURRENT_PROJECT_VERSION 2` (`project.pbxproj:299,306,328`).
- **Android** — Bundle `com.replab.fitness`; targetSdk 36, minSdk 24 (`variables.gradle:2-3`); plugins registered in `client/android/capacitor.settings.gradle:2-24`: same seven, **also missing `@capacitor-firebase/messaging`**. App Links intent-filter on `replab-fitness.com` + `www.replab-fitness.com` is wired (`AndroidManifest.xml:32-39`) with `autoVerify="true"`. `POST_NOTIFICATIONS` permission declared. No `google-services.json` — `app/build.gradle:48-53` explicitly logs that push won't work if absent.
- **Web** — SPA served by Express; `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json` are dynamically rendered from env (`server/index.js:191-217`) but default to placeholder `TEAMID` and zeroed SHA-256 (`server/config.js:22-26`). PWA service worker present (`client/public/sw.js`).

## High-risk findings

- **H1 — Keyboard handling unconfigured.** `@capacitor/keyboard` is **not installed** (Grep `@capacitor/keyboard` in `client/` → 0 hits) and not in `capacitor.config.json`. Default Capacitor iOS behavior is `resize: 'native'` which does push content, but without the plugin you cannot adjust mode or listen to `keyboardWillShow`. WorkoutSession set-logging inputs (highest-volume input flow) may be hidden behind the keyboard on small iPhones. **Recommendation:** install `@capacitor/keyboard`, set `resize: 'body'`, and verify the sticky exercise header in `WorkoutSession.jsx:2225` doesn't trap the focused input.
- **H2 — `@capacitor/haptics` shipped but unused; iOS gets no vibration.** Plugin is in `package.json:18` and registered in both SPM + gradle, but **Grep across `client/src` shows 0 imports**. All vibration goes through `navigator.vibrate?.(…)` in 13+ call sites (`WorkoutSession.jsx:451,1687,1724,1783,2022`, `ExerciseCard.jsx:150,885`, `Utilities.jsx:313,319,327`, `CardioAccelerationCard.jsx:86`, `FeaturedWorkoutSession.jsx:1145`, `ExerciseCardTest.jsx:64`). WKWebView **does not implement** `navigator.vibrate` — iOS users get no haptic feedback on rest-timer alerts, set complete, PB hit, or any other event. Android Chrome supports `navigator.vibrate` so Android works. The comment at `WorkoutSession.jsx:451` ("iOS Safari ignores vibrate") acknowledges this but no fallback is wired. **Recommendation:** add a thin wrapper `utils/haptics.js` that calls `Haptics.impact({ style })` on native and falls back to `navigator.vibrate` on web; swap all 13 call sites.
- **H3 — `@capacitor/preferences` shipped but unused; auth lives in `localStorage`.** Plugin registered in both SPM + gradle but **Grep `@capacitor/preferences` across `client/src` → 0 hits**. Refresh token + user blob are in `localStorage` (`api.js:33`, `AuthContext.jsx:30`). On iOS, `localStorage` in WKWebView is in a sandbox that *can* be cleared by the OS under storage pressure, kicking the user out without warning. **Recommendation:** wrap `setRefreshToken` / `getRefreshToken` to write to `Preferences` on native (durable, not wiped) while keeping `localStorage` for web. Currently the in-memory fallback (`api.js:3-23`) helps Safari Private Mode but doesn't survive a process kill on native.
- **H4 — Status bar never explicitly styled on Android.** `capacitor.config.json:10-12` sets `StatusBar: { style: 'DARK' }` which on Android sets light icons on a dark bar — but the **background color is unset**, so on Android 6+ the bar inherits the theme color (likely white). Status bar text + icons will be invisible against the dark default bar on some Android skins. iOS auto-syncs from the storyboard so it's OK. **Recommendation:** add `backgroundColor: '#000000'` and `overlaysWebView: false` to the StatusBar plugin config and/or call `StatusBar.setBackgroundColor({ color: '#000000' })` once on mount.
- **H5 — System back button (Android) is not handled.** Grep `backButton` in `client/src` → 0 hits. The default Capacitor `@capacitor/app` plugin will **background the entire app** on first back-button press when modals are open, mid-workout, mid-form, etc. Play Store review will not block on this, but it's a 1-star review machine. **Recommendation:** add a global `App.addListener('backButton', ({ canGoBack }) => { if (modalOpen) close(); else if (canGoBack) window.history.back(); else App.exitApp(); })` in `App.jsx` mount.
- **H6 — External links bypass `@capacitor/browser`.** Four sites use `target="_blank"` (`Workouts.jsx:723,2098`, `VideoPlayerContext.jsx:204`, `RepLabFeedTest.jsx:769`). On Capacitor iOS this either no-ops or loads inline in the WKWebView depending on Capacitor version (8.x defaults to opening in Safari, but the YouTube link at `VideoPlayerContext.jsx:204` and the PDF link at `Workouts.jsx:2098` are user-touchable in the main authed flow). **Recommendation:** install `@capacitor/browser` and replace the 4 anchors with a `openExternal(href)` helper that calls `Browser.open({ url })` on native.
- **H7 — Sentry has no platform tag.** `client/src/sentry.js:6-23` initializes with `environment` only. iOS, Android, and web errors all land in the same bucket. **Recommendation:** after init, call `Sentry.setTag('platform', Capacitor.getPlatform())` (returns `'ios' | 'android' | 'web'`).

## Medium findings

- **M1 — Splash screen storyboard targets retina4_7 (iPhone 6/SE 1st gen).** `LaunchScreen.storyboard:3` declares `device id="retina4_7"`. The image asset itself is 1366×1366 (square) which Capacitor recommends — but the storyboard config means modern devices may letter-box. Re-export from a fresh `npx cap sync ios` to regenerate against current devices.
- **M2 — `safe-bottom` on `BottomNav` is double-applied.** `BottomNav.jsx:59` uses `safe-bottom` (padding), but `Layout.jsx` already accounts for `var(--rl-nav-clearance)` which itself includes `env(safe-area-inset-bottom)` (`index.css:362`). Result is fine on iPhones but on Android with a gesture nav bar the bottom tab labels may sit higher than expected. Verify on Pixel/Samsung.
- **M3 — WorkoutSession full-screen overlay has top safe-area but no bottom.** `WorkoutSession.jsx:2225-2240` portal applies `paddingTop: 'max(8px, env(safe-area-inset-top))'` to the bar but the bottom of the overlay has no `safe-bottom`. On iPhone X+ the bottom inputs (set logging row) can sit under the home indicator. Add `paddingBottom: env(safe-area-inset-bottom)` to the bottom content area.
- **M4 — Public landing `/` redirects native to `/app`.** `App.jsx:159-165` correctly hides the marketing page on native, but if Capacitor cold-launches with no auth + slow network, the user sees a black screen until `/login` resolves. Combined with B1, this is the cold-launch hang. Worktree `aee965f608eaec7f9` (A11Y live regions) may help but doesn't fix this.
- **M5 — `target="_blank"` PDF download in Workouts will misbehave on iOS.** `Workouts.jsx:2095-2109` uses `<a href={pdfUrl} download target="_blank">`. The `download` attribute does nothing in WKWebView; on iOS, this opens the PDF inline in the same WebView with no nav to escape. Wrap with `@capacitor/browser` (see H6).
- **M6 — iOS portrait-only, iPad allows all 4 orientations.** `Info.plist:35-45` enables landscape on iPad but the SPA has no landscape layout (no `landscape:` Tailwind, no orientation-aware components). Combined with B7 this will result in unusable iPad-landscape screens. Strip iPad orientations or drop iPad target.
- **M7 — Capacitor 8.x plugin versions are consistent** across `package.json:14-23` (all ^8.0.1–^8.3.1) and SPM + gradle. No version drift between iOS and Android registrations. Verified clean.
- **M8 — `worktree-agent-aee965f608eaec7f9` and `-ae4c31e265775085f`** (A11Y) may add additional `aria-modal` and focus traps to modals; verify they don't conflict with the Android back-button handler proposed in H5.
